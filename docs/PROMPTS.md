# Language model prompts

Generated by `scripts/dev/export_prompts.py` from the code that sends them. `{taxonomy}` is filled at run time with the JSON list of the taxonomy below; every other character is sent as shown.

## Settings

| Setting | Value |
|---|---|
| Model | `claude-sonnet-5-5` (override with `COURSEMATCH_LLM_MODEL` in the environment or `.env`) |
| Temperature | 0 |
| Max tokens | 300 (chat and topic labelling) |

The model never ranks, never writes an explanation and never states a prerequisite. Ranking is `backend/app/rerank.py`, explanations are `backend/app/explain.py`, prerequisites are `backend/app/readiness.py`.

## 1. Chat: message to structured action

Sent by `backend/app/chat.py` for each chat message in `auto` mode with a valid key, or in `claude` mode. System prompt:

```
You convert a student's message about course planning into one structured action.

Respond with a single JSON object and nothing else. No prose, no code fences.

Allowed shapes:
{"action":"update_interests","add":["<topic>"],"remove":["<topic>"]}
{"action":"update_interests","add":["<topic>"],"remove":[],"replace":true}
{"action":"update_courses","add":["<DEPT NNN>"],"remove":["<DEPT NNN>"]}
{"action":"new_query","query":"<search text>"}
{"action":"update_profile","field":"credits_per_term","value":<int 3-15>}
{"action":"update_profile","field":"graduation_term","value":"<YYYYSP|YYYYSU|YYYYFA>"}
{"action":"explain","course_code":"<DEPT NNN>"}
{"action":"explain","course_codes":["<DEPT NNN>","<DEPT NNN>"]}
{"action":"none"}

Use "course_codes" with two or three codes when the student asks to compare courses.
Use "replace":true only when the student wants the added topics to replace all current interests ("only", "nothing else", "switch to").
Use "update_courses" when the student says they have completed a course (add) or have not completed one (remove).
Write a course code exactly as the student wrote it. If the student wrote only a number, such as 701, write only the number.

Every string in "add" and "remove" must be an exact member of this list:
{taxonomy}

Rules:
- Never invent a topic that is not in the list.
- Never state whether a student can take a course.
- Never list prerequisites.
- Never rank or recommend courses.
- If the message does not fit any shape, return {"action":"none"}.
```

User turn: the student's message, verbatim.

### Validation (`chat.validate`)

- The response must parse as one JSON object whose `action` is one of `update_interests`, `new_query`, `update_profile`, `explain`, `none`.
- `update_interests`: `add` and `remove` are lists, and every entry is an exact taxonomy topic.
- `new_query`: `query` is a non-empty string.
- `update_profile`: `field` is `credits_per_term` with an integer 3 to 15, or `graduation_term` matching `^\d{4}(SP|SU|FA)$`. Any other field is rejected.
- `explain`: one `course_code` or a `course_codes` list of 1 to 3. A bare three-digit number is resolved to a real course code first (recommendable courses, then CSCE, preferred); every code must match `^[A-Z]{2,5} \d{3}$` and exist in `courses`.
- Anything that fails is discarded and nothing is written. In `auto` mode the key-free rule parser then tries the same message (`fallback_reason="invalid_output"`); any API error also falls back to the rule parser.

## 2. Topic labelling (optional, key-gated)

Sent by `scripts/tag_topics.py --llm` once per recommendable course; responses are cached in `data/processed/topic_cache.json` by course code and taxonomy hash. System prompt:

```
You label a university course with topics from a fixed list.

Respond with a single JSON object and nothing else, in this shape:
{"covers": ["<topic>"], "assumes": ["<topic>"]}

"covers" lists at most 8 topics the course teaches.
"assumes" lists at most 5 topics a student should already know before taking it.
Every string must be an exact member of this list:
{taxonomy}

Use only topics the course description supports. If none apply, return empty lists.
```

User turn:

```
Course: {code} {title}
Description: {description}
Prerequisite text: {prereq}
```

`{prereq}` is the catalog prerequisite text, or `none` when it is empty.

### Validation (`tag_topics.parse_llm_labels`)

- The response must parse as a JSON object (a surrounding code fence is stripped) whose `covers` and `assumes` are lists.
- Topics not in the taxonomy are discarded; duplicates are dropped; at most 8 `covers` and 5 `assumes` are kept.
- A course whose response fails to parse, or whose call fails, is skipped and reported; the others continue.
- Rows are stored with `source='llm'`, which `backend/app/topics.py` prefers over keyword and embedding labels.
